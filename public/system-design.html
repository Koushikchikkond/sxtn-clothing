Edge Middleware

Intercepts incoming traffic and applies an Upstash Redis sliding window limiter on /api/checkout and auth routes to stop DDoS bots.

Database Architecture

PostgreSQL 15 on Supabase with strict Row Level Security (RLS) policies and atomic PL/pgSQL stored procedures.

Asynchronous Webhooks

Dual webhook receivers for Razorpay (financial reconciliation) and Shiprocket (real-time package transit milestones).

Zero-Trust Client Pricing

Frontend prices are completely ignored during order creation. /api/create-order queries live PostgreSQL prices and computes the true mathematical sum.

HMAC-SHA256 Integrity

Orders cannot be forged. Razorpay's cryptographic signature must match order_id + "|" + payment_id hashed with RAZORPAY_KEY_SECRET.

Fallback Webhook

If the user closes their browser right after paying, /api/webhooks/razorpay receives the asynchronous event and writes the order automatically.

🛡️ 3. Atomic Inventory Concurrency Guard

How race conditions, double-orders, and overselling are eliminated during high-traffic drops using a 3-layer guard and PostgreSQL row locks.

flowchart TD subgraph Layer1["Layer 1: Frontend Guard (Zustand Store)"] A[Customer selects quantity] --> B{Qty <= Available Stock?} B -- Yes --> C[Added to Bag Store] B -- No --> D[Capped at max available stock] end subgraph Layer2["Layer 2: Server Verification Guard (/api/create-order)"] E[Customer clicks Checkout] --> F[calculateVerifiedCartTotal] F --> G[(Query DB Variants Stock)] G --> H{Requested Qty <= DB Stock?} H -- No --> I[Abort: 400 Out of Stock Error] H -- Yes --> J[Generate Razorpay Order] end subgraph Layer3["Layer 3: Atomic Stored Procedure Guard (decrement_variant_stock)"] K[Payment Verified Successfully] --> L[Call RPC: decrement_variant_stock] L --> M["BEGIN TRANSACTION
SELECT stock FROM product_variants WHERE id = p_variant_id FOR UPDATE"] M --> N["UPDATE product_variants
SET stock = GREATEST(0, stock - p_quantity)
WHERE id = p_variant_id"] N --> O[(CHECK constraint: stock >= 0)] O -- Passed --> P[COMMIT TRANSACTION: Stock Safely Deducted] O -- Failed --> Q[ROLLBACK: Transaction Aborted] end Layer1 --> Layer2 Layer2 --> Layer3

Row-Level Locks

The stored procedure uses row locks so multiple simultaneous buyers of the same size are processed in strict atomic sequence.

Database Constraint Net

Even in an unexpected edge case, the database engine schema has CHECK (stock >= 0), making it mathematically impossible for stock to become negative.

Token Caching

Shiprocket JWT tokens are cached in memory for 9 days (valid for 10) to eliminate redundant login roundtrips.

Automated Courier Choice

Shiprocket's CORE engine automatically picks the fastest and highest-rated courier (Bluedart, Delhivery, etc.) for the customer's pincode.

Customer Tracking Portal

Orders store direct tracking URLs (https://shiprocket.co/tracking/:awb) rendered in the customer's account order view and emails.
